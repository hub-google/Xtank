# X-TANK 正式公網 WSS：部署與實機驗收

> 開發狀態（2026-10-27）：程式、Docker、部署藍圖已提交 GitHub；**尚未證明有一台全天候在線的公開 WSS 主機**。以下設定不代表已完成部署。

## 1. 正式伺服器（避免用 GitHub Actions 假裝 24 小時主機）

- `render.yaml`：Render web service，Singapore region，Docker，單一節點，`/health`，持久化儲存掛載在 `/data/settlements`。
- `Dockerfile`：建置權威引擎並以非 root Node.js 身份運行，監聽 `0.0.0.0:8787`。
- 正式模式 `XTANK_OFFICIAL_MODE=1`，`SUPABASE_URL` 指向 Game 專案；`SUPABASE_SERVICE_ROLE_KEY` **只在 Render 機密環境變數設定**。任何情況都不可 commit 到 GitHub、前端、EXE 或公開 Actions log。
- `XTANK_SETTLEMENT_DIR=/data/settlements` 必須具有可寫的持久化磁碟，否則資料庫暫時故障期間未結算的比賽可能隨容器重啟遺失。
- Render 永久磁碟只支援付費服務，並限制為一個實例；`render.yaml` 使用最小的付費計算方案與磁碟。**新增藍圖不會自動建立收費資源**，需由有權限的 Render 帳號啟動並決定是否接受費用。
- Render 的 HTTPS 反向代理會將公開端點提供為 `https://<實際分配網域>/health` 與 `wss://<實際分配網域>`。**部署前不能虛構網域或宣稱在線**。
- 官方模式需要兩個已登入的正式 Supabase 玩家同局；私人 LAN 和純單機仍屬 practice，不授予真實金幣／XP。

官方部署完成後，先開啟分配的 `/health` 驗證 JSON `{"ok":true}`，再從兩台不同網路上的 Windows EXE 輸入相同 WSS 網址，各以不同玩家帳號登入並加入同房。

## 2. 上線前必要核對

1. Render 上的 `SUPABASE_SERVICE_ROLE_KEY` 只在伺服器端存在；GitHub Actions 和 EXE 均沒有相同權限的明文。
2. HTTP health check 成功，正式 WebSocket 經 `wss://` 可連接，測試 token 無效時不得進入房間。
3. 以 qa-a、qa-b 真實玩家完成：登入 → 商店購買 → 裝備 → 建房／加入 → READY → 倒數 → 對戰 → 結算 `MATCH_SAVED` → 返回房間 → 再戰。
4. 核對 `xtank.matches`、`xtank.match_rewards`、`wallet_transactions`、`xp_transactions`、`inventory_ledger`；相同 `server_round_id` 不得雙倍入帳。
5. 模擬 DB 短暫中斷和容器重啟；持久化 outbox 能補送，已在 UI 顯示 `MATCH_SAVED` 並可再戰。
6. 至少由兩個獨立公網出口測試 Windows EXE（不是兩個只連 `127.0.0.1` 的視窗），涵蓋斷線、重連、房主退出、下局及戰績跨裝置持久化。
7. 觀察端到端延遲、CPU、記憶體和長時測試；未經證據不得標記正式版 PASS。

## 3. Windows EXE 自動測試

- `.github/workflows/windows-exe.yml` 單一工作流程，在 `main` 的程式推送執行 Node 測試、Docker health check、Windows portable EXE 打包、8 車 × 3 模式 × 3 地圖共 **72 個 GUI 冒煙情境**及核心 A/C 測試。
- 手動執行該工作流程時，`qa_filter=^` 才啟用完整 GUI C/D 測試（包括原生 Windows 雙視窗 LAN 真人連線測試）；這仍不是跨不同公網的正式伺服器驗收。
- 通過 GitHub Actions 只能表示該次實際執行的 case 通過；不要把 SKIPPED/BLOCKED 案例計算成 PASS。

## 4. 實際剩餘外部動作

必須將 GitHub 倉庫部署至可常駐的 Render 服務，注入服務端機密，取得真實 WSS URL，才能驗收正式公網雙人流程。這一步不能透過單純 Push 程式碼、GitHub Pages 或 GitHub Actions 常駐 runner 自動達成。

參考官方規格：
- Render Blueprint: https://render.com/docs/blueprint-spec
- Render persistent disks: https://render.com/docs/disks
- Render health checks: https://render.com/docs/health-checks
