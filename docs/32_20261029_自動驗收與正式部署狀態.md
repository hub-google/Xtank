## 3. 真實問題、修復與精準重測

1. **原始 30 分鐘測試 FAIL 是 QA 測試玩家流程問題，不是已證實的伺服器效能崩潰。** 測試腳本只讓房主送 `BACK_TO_LOBBY`，但遊戲協定要求所有玩家個別確認後才重開。修正 `scripts/soak-wss.cjs`：8 位測試玩家各自確認，等待全部回大廳；主線 commit [0bd52e4](https://github.com/hub-google/Xtank/commit/0bd52e4e14aacc44ea598985b132e54ba3ef5e8b)。測試專用自然回合縮短開關僅允許 `NODE_ENV=test`，commit [2966941](https://github.com/hub-google/Xtank/commit/29669419024c8494f8285d4088d5cbaa7a10ef47)。兩項均由 Run 40811018490 的兩個成功 job 驗證。
2. **原生雙 EXE 工作仍有 GUI QA 失敗。** `results.json` 定位於 `scripts/windows-gui-qa.cjs` 的 `#hostServerButton` 點擊逾時；失敗截圖顯示可捲動首頁面板，兩個原生視窗的桌面截圖均存在。這只能證明 GUI 自動化未完成，不能由此斷言 LAN 伺服器本身壞掉。已改為先把實際 EXE 視窗置前、捲動至按鈕、檢查真實可點擊區，再送出**真實 CDP 滑鼠輸入**（不直接呼叫 DOM click）。主線修正 commit [f2d422e](https://github.com/hub-google/Xtank/commit/f2d422e9a1169e242c16cc44863201be5771a2e1)，另修正無 viewport emulation 的原生視窗尺寸判定 commit [3ec384a](https://github.com/hub-google/Xtank/commit/3ec384a121d3c9a44e6ffe6bfe03290207bf53b0)。
3. **最小精準重測**：[40815502134](https://github.com/hub-google/Xtank/actions/runs/40815502134)，驗證分支 `release-validation/2026-10-29-dual-exe-click-regression`，程式 blob 與 main 修正相同；只重新建置最新原生 Windows EXE 並執行 `^D-LAN-create-join-start-sync-reconnect$`，不重跑 30 分鐘已 PASS 負載，也不把未跑案例標 PASS。**本頁寫入時仍在執行，尚不可宣稱重測通過。**
