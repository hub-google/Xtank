## 2. 已實際執行的驗證
- 2026-10-27：Supabase Edge Admin API 建立三位 `auth.users`，`email_confirm=true`。
- `xtank.qa_credentials.account_user_id`、`provisioned_at` 皆不為 NULL。
- 向 `/auth/v1/token?grant_type=password` 發送三位帳號的正式密碼授權，HTTP **200/200/200**（request IDs 2/3/4）。
- 使用三筆真實登入的 access token，呼叫 `/rest/v1/rpc/xtank_player_api` 的 `dashboard`，HTTP **200/200/200**（request IDs 5/6/7）。
- 以上是 **Auth/API 整合驗證，不是 Windows EXE GUI 實測**；Windows GUI 流程要獨立執行。

## 4. 清理與維護
- 帳號密碼可在管理環境透過 Supabase Admin API 重新輪替，再同步更新 `xtank.qa_credentials`；**不能只更新 QA 表而不修改 Auth 密碼**。
- `xtank.qa_credentials`、`xtank.qa_bootstrap` 均為私有 `xtank` schema，RLS 開啟，不給 anon/authenticated 直接表權限。
- 一次性的 `xtank-qa-bootstrap` Edge Function 所用 nonce 已標記 consumed，不能重複呼叫建新帳號。
- 如果多人測試把初始金幣改變，測前及測後要保存測試帳號錢包快照；不要靠手動改 balances 來假裝完整交易成功。
