# 20｜內容 JSON、事件協定與版本契約 v0.1

目標是讓「文獻→配置→伺服器→前端」只需要一套資料，不要把規則重寫在多處。下列範例是 **P 建議形狀，不代表已存在實際程式碼**。

## 1. 規則與來源對照
配置目錄候選：
- packages/shared/src/schema/{tank,weapon,item,map,mode,room}.ts
- packages/shared/data/{tanks,weapons,items,modes,maps}/*.json
- packages/server/src/{match,physics,collision,damage,rooms,economy}/
- apps/web/src/{scene,net,input,ui}/

所有 gameplay 數據由伺服器載入、驗 schema、再給前端只讀版本；網頁打包資源版本必須相同。

## 2. 傳輸封包型態（P）
| 方向 | type | 必需欄位 | 驗證 |
|---|---|---|---|
| Client→Server | HELLO | protocolVersion, sessionToken, buildId | 驗證身份與版本 |
| Client→Server | JOIN_ROOM | roomId, password? | 容量、房主、密碼、可加入狀態 |
| Client→Server | INPUT | seq, clientTick, axisX, axisZ, yaw, fire, weaponSlot, itemSlot, ability | 限速、slot、cooldown、sessionEpoch |
| Client→Server | READY | ready | OPEN/READY_CHECK 才接受 |
| Server→Client | JOIN_ACK | playerId, roomVersion, serverTick, reconnectToken | 不外洩密碼 |
| Server→Client | SNAPSHOT | tick, ackSeq, entities[], score, flagState | 每個連線允許可視資料 |
| Server→Client | MATCH_EVENT | eventId, tick, eventType, payload | 可重放且同 id 只計一次 |
| Server→Client | RESULT | matchId, rulesetVersion, results[], rewardSummary | 只由伺服器產生 |
| Server→Client | ERROR | code, message | 人類可讀但不洩漏內部細節 |

INPUT 一個包中可打包自上次 ack 後多次未確認命令，但每 seq 只處理一次、限制補送數量和最大時間跨度。對武器作 serverTick 綁定的 fire edge 處理，杜絕反覆重送重複射擊。

## 3. 狀態機不變量（P）
- playerId + matchId 在任一伺服器 tick 最多只有一個生命有效體。
- hp∈[0,hpMax]、shield∈[0,shieldMax]；若 hp≤0 就不能同 tick 再發生第二次死亡。
- room.phase != LIVE 不允許傷害或累積正式比分。
- flagHolder 只能是 null 或現存活且合法的 playerId；一旗不得同時被兩人佔有。
- 貨幣交易和 match 結算都以 idempotency key 原子提交。
- 地圖 spawnPoint 必須在 walkable navmesh，且不與 collider 重疊。

## 4. 版本升級契約
protocolVersion 以 major/minor 區分破壞性變更；rulesetVersion 改動傷害或計分；assetManifest hash 改動美術資產。任意 mismatch 在 JOIN 階段回報，提示重新整理，不要在打到一半悄悄更換規則。

## 5. 測試資料
建立 fixture：2 players FFA、4 players TDM、8 players FLAG_HOLD、敵我同位置衝突、兩人同 tick 拿旗、舊 sessionEpoch、彈量耗盡、伺服器重啟重放獎勵、10% 抖動/封包丟失。用 deterministic seed 和事件 log 可回放比較伺服器 state hash。
