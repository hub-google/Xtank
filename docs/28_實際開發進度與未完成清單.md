## A. 已確實完成並有證據
- 正式 Supabase Game `xtank` 私有 schema：62 張資料表 + 62 張 RLS，及玩家建檔、金幣、XP、商城、正式對戰獎勵的資料庫交易函式（尚不是完整可玩的所有業務流程）。
- 已部署 `public.xtank_player_api`：經 Supabase Auth JWT 驗證後可初始化玩家、讀自己的 Dashboard、查商品表、購物、升級點及排行榜。
- 已部署 `public.xtank_save_loadout`：登入玩家可為已擁有坦克保存有物品所有權校驗的配裝。
- 已部署 `public.xtank_social_api`：好友列表、邀請、接受和封鎖的後端操作。
- 已部署 `public.xtank_record_official_match`：僅 service_role 可呼叫，單一交易寫入權威對局、真人/AI 參戰資料、XP/COIN/戰績及重送結果。仍須正式遊戲伺服器端到端驗證。
- 新增 `server/official.cjs` 與 `server/host.cjs` 官方模式適配：要求伺服器端 service key、登入玩家 JWT、驗證坦克與已配武器，權威對局結束時嘗試結算；LAN 未提供官方權限時仍可玩，但不得發官方獎勵。
- 新增 `test/official-service.test.cjs` 單元測試：伺服器缺密鑰拒啟、玩家身份和武器校驗、權威勝負資料向資料庫服務送出。
- `src/account.js`、`src/account.css`：已新增註冊/登入/遊客、玩家 Dashboard、機庫、商店、配裝、好友、排行、設定入口，且入口嵌入 `index.html`。**有程式碼不等於原生 EXE GUI 已通過**。
- 3 組真實 `auth.users` QA 帳號已建立且各自有玩家檔、8 輛坦克及起始金幣；密碼存私有 `xtank.qa_credentials`，讀取方式見 27，勿放公開 repo。
- Auth 登入 HTTP 200 × 3，真實玩家 Dashboard RPC HTTP 200 × 3。
- qa-a 用資料庫商店函式實際購買 mine 並以相同 key 重送，兩次返回相同訂單、只扣一次幣/發一次物品；HTTP 玩家 JWT 購買 chemical 的 RPC 返回 200。
- qa-a 透過 JWT RPC 保存一份 X-TANK 配裝，HTTP 200，`xtank.loadouts` 查到實際資料。
- 原型程式現有：單機 AI、8 車、3 地圖、3 模式、7 武器、6 道具、LAN WebSocket 房間和基礎遊戲結算。

## C. 已有測試但不能替代完整 QA
- 靜態 JS 語法檢查及 Windows Actions `npm test`、`npm run build` 是編譯與單元測試，不等於原生 EXE 的登入、商城、正式線上對戰測試。
- QA 測試帳號與三組金幣是**測試資料，不是真玩家或完整帳號服務**。
- 每次實際改動資料庫必須更新 `supabase/migrations`，程式功能驗證必須有 Windows action run ID 及實機截圖/trace/證據。

## D. 下一輪開發最有價值的驗收順序
1. 將登入畫面真實使用 Windows EXE 點選測試，驗證三個 QA 帳號可進入玩家中心，並跑商城/配裝永久資料。
2. 實作獨立持續運作的官方權威 WSS 與 JWT 驗證，不使用玩家自建 LAN 發金幣。
3. 實作權威賽果 → 交易原子化 → 客戶端顯示獎勵 → 重開 EXE 資料仍在。
4. 完成準備房間、完整武器/坦克配裝、社交與成長、任務活動；最後依 26 完整測試。
