## 1. 產品定位與完成定義
重製受 2000–2002 X-TANK ONLINE 啟發的第三人稱迷你坦克戰鬥。核心循環：
**開啟 EXE → 身分驗證 → 個人機庫/主大廳 → 配裝/商店 → 選模式 → 房間/配對 → 戰前準備 → 3D 對戰 → 權威結算 → 經驗與遊戲幣/成就入帳 → 升級/換裝 → 再戰/退出。**

成功條件：玩家 A / B 在不同網路、兩台真正的 Windows 電腦上，從安裝或解壓到登入、互相看到、交火傷害同步、自然結束、正式戰績只入帳一次、關閉 EXE 再開後資料一致。無法達成，不宣稱完整多人遊戲。

### 1.1 版本與史實
- H1：當年一手新聞/手冊可證。H2：後世整理。P：本專案為可玩性提案。U：未考證。
- H1、H2、P、U 必須標在遊戲內容與數值來源；不得拿提案冒充官方原始設定。
- 未獲授權，不得納入原始客戶端、美術、音樂、商標、地圖及其他素材。
- 數值都綁 `ruleset_id` 與 `build_version`，正式舊賽果不得被新版數值改寫。

## 2. 玩家角色、服務分層
- 訪客：可立即進練習，匿名 Auth 帳號可在升級為永久帳號時保留同一 player_id。
- 正式玩家：帳號/密碼或支援的登入方式，跨裝置讀取進度；遊戲幣/經驗只來自權威伺服器。
- 房主：改房間設定、邀請/踢人、開局；不能決定傷害/勝負/發獎。
- 管理員：調整活動/素材/規則、封鎖/申訴、稽核經濟，不與玩家權限混用。
- 客戶端 EXE：只負責 UI/3D 渲染、預測與輸入，不直接持有 Supabase service secret。
- 官方 WebSocket 權威伺服器：合法行為驗證、碰撞、命中、重生、計分及可信戰局摘要。
- Supabase：Auth、PostgreSQL、Storage；部署於既有 Game 專案的私有 `xtank` schema，後端服務呼叫，並不自動開放成 REST。
- LAN 玩家自建主機屬 community/practice，不可直接發正式金幣或排位分數。

### 3.1 新手首局 (U1)
1. 直接啟動 portable EXE，任一畫面明確顯示程式版本與網路狀態。
2. 訪客模式不要求電子郵件；可選 X 坦克，3 次主要操作內進入 AI 練習。
3. 進局前顯示 WASD、滑鼠、左鍵、1–7、F1–F6、E、P、Esc。
4. 練習不發正式競技獎勵；結算可再戰或回大廳，退出無當機。

### 3.2 已註冊玩家 (U2)
1. 登入（Auth session）；player_id 一致；若玩家 profile 不存在，以可信後端初始化，預設金幣/車種由函式控制。
2. 大廳載入機庫、背包、配裝和貨幣；兩裝置登入同步且可規範同時正式對戰席位。
3. 商品購物只透過後端，成功扣款 + 交付物品原子交易；失敗不扣錢。
4. 官方伺服器開局前，鎖定武器裝備、屬性及規則版本。
5. 戰鬥結束後，後端先確定權威賽果，再一次性發放 XP/COIN，玩家看見領取結果；重登入後維持一致。

### 3.3 多人房 (U3)
1. 官方房間有公開列表、房名/房碼、地圖、模式、規則、容量 (2–8)、密碼（雜湊不可回傳）。
2. 第九人禁止加入；已開打依規格拒絕或只能旁觀。準備和開始權限按房主角色檢查。
3. LIVE 期間 30 秒重連到原 player slot，恢復同一伺服器 tick 真相；逾時有可讀錯誤。
4. 房主離線時發生主持權移交；正式戰鬥伺服器不隨客戶端 EXE 關閉而消失。
5. 同一戰局的所有客戶端比分、死傷、持旗者與勝負一致。

## 4. 三種戰鬥模式
| mode_id | 規則 | 當前 simulation.js 0.2.2 | 最終設計 |
|---|---|---|---|
| FFA | 每擊殺計 1 分，先達標或時間到結束 | 12 擊殺／300s；單機 4 台、多人可 8 台 | 可配置限制；競技公平與排名 |
| TDM | 紅藍兩隊擊殺計分 | 30 分／480s；4v4 | 人數/隊伍平衡檢查、準備狀態 |
| FLAG_HOLD | 持一面旗累計時間得分 | 連續持旗 15s 得 1 分；5 分／480s | 與 2002 史料一致的持旗玩法，不與奪旗回基地混淆 |

場景：`desk` 巨型書桌、`chess` 棋盤、`circuit` 電路板。當前自製模型不是 1:1 歷史素材。每個 MapDefinition 要有對應碰撞、障礙、出生點及旗點。

## 5. 戰鬥與操控
- 8 車：X、D、M、R、H、A、O、S，基本數值見 `src/simulation.js` 及 `docs/14`。
- 武器已實作 7：hurricane、death_knight、vulcan、plasma、chemical、ion_missile、mine。
- 道具已實作 6：repair、speed_boost、shield_cell、radar_ping、smoke、team_repair。
- 車種技能：nitro、accel、defense、radar、invisible。所有效果仍需交叉測試。
- 控制：WASD 移動、滑鼠瞄準、左鍵/Space 射擊、1–7 換武器、F1–F6 道具、E 技能、P/Esc 暫停與主畫面。
- 權威規則：僅接受輸入而非客戶端自報命中/HP/錢/經驗；60Hz/快照頻率須經實測而非紙面承諾。
- 命中傷害先盾後血、發炮冷卻/彈量/視野/碰撞、復活、AI 避障、小地圖、旗一人持有的原子性須被測試。
- 低效能硬體應降畫質但不得降低邏輯時鐘速度；本專案先前曾有 GPU 低 FPS 使模擬時間過慢的缺陷，須加入回歸項目。

## 6. 永久成長及經濟
- 玩家總等級、各坦克熟練度/等級、五屬性點（Speed/Attack/Defense/Energy/Collision）、解鎖、背包、可儲存配裝。
- 貨幣預設 `COIN`；新玩家初始 1000 COIN 是 P 提案；練習/自建 LAN 不得發正式獎勵。
- 同局獎勵以 `(match_id,player_id)` 唯一；商店購買採 idempotency key；交易/物品/經驗一起成功或一起失敗。
- 不得把 `localStorage` 或 EXE 的金幣視為真實；DB 才是永久來源。
- 經典成長房與標準化競技房分離，避免新手被累積數值碾壓。
- 退款、補償、購物/經驗調整必須留下 ledger 和稽核紀錄。
- 排名、賽季、任務、成就、活動、好友、公會與系統郵件屬正式產品能力，按階段上線。

## 7. 安全、可用性與營運
- 身分：Supabase Auth user ID 對應 xtank.players.player_id；用戶端只能拿公開 publishable key，絕不能內嵌 service_role / DB password。
- 授權：xtank 私有 schema、不公開 Data API，所有 62 表 RLS on；敏感寫入走可信任後端。
- 客戶端每次連線提供 Auth access token，伺服器以遠端 JWT 公鑰/官方驗證機制核對身份、session、權限與封鎖狀態；房碼不能充當登入憑證。
- SSL/TLS + WSS，會話失效、速率限制、重送/倒序/作弊封包、封禁、惡意聊天、個資刪除與匯出規範。
- 非功能目標（尚待量測）：Windows 10/11 x64、1366x768+、啟動錯誤可觀測、低 FPS 不使對局計時走慢、持續兩小時不無限成長記憶體、兩網真人全流程可玩、8 人房穩定同步。
- 官方多人伺服器須可公開連線且可營運；GitHub Pages 及 Supabase DB 本身不等於常駐遊戲伺服器。
